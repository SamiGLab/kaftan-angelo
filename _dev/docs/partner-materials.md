# Partner materials — website integration

The current desktop contract is `materials: {code, draft, version, storage_code?, files}` in the successful `get_partner_portal` response. Each file has `{filename, format, language, type, sha256, url}`. Supported formats: `card` (10×15 cm), `poster` (A4), `mobile` (9:16); languages: `hu`, `en`; types: `pdf`, `png`. A complete set has 10 files and displays six cards: PDF+PNG for card/poster in each language and PNG for each mobile invitation.

The website uses `files.url` directly. Do not reconstruct paths from partner codes: non-ASCII codes can have a hashed `storage_code` folder. `code` must match the authenticated partner if present. `draft=true` displays a draft warning. Only HTTPS links without embedded URL credentials are rendered, using DOM textContent. The earlier array `{partner_code, kind: print|mobile, language, pdf_url, png_url, preview_url?}` remains supported for compatibility.

Missing/empty materials display preparation notices; this does not prevent login. Preview failures retain download links and show recovery text. Logout clears previews and material links. PDF links use the browser viewer for printing, PNG links can be saved and attached to a private chat; no native public sharing sheet is invoked.

Coordination: desktop owns generation, QR correctness, uploads, and partners.materials metadata; Supabase returns the validated partner's materials; website owns rendering. This change does not alter SQL, PIN validation, grants, commissions, or database records. These promotion files are currently supplied through a public Storage bucket. Do not put PINs, banking data, or confidential contracts into promotion files; upload permissions must remain restricted to the trusted uploader. For future private buckets return fresh signed URLs from a trusted backend, never a browser service-role key.

Verify with `npm run build:astro`, `npm run check:all`, and `node _dev/scripts/test-partner-portal.mjs`. Tests cover empty data, the current ten-file manifest, legacy arrays, mismatched partner codes, unsafe URLs, HU/EN, logout and mobile layouts. Desktop's live verification is recorded in kaftan-desk/output/partner-materials/supabase-integration-check.json; final live browser verification is separate.
